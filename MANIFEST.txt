ZIP: hyascka-fix-image-loader-crash.zip
Small patch fixing the exact crash you reported:

  Error: Functions cannot be passed directly to Client Components unless
  you explicitly expose it by marking it with "use server".
    <... src=... alt=... fill={true} sizes=... loader={function} ...>

WHAT TO DO:
1. Overwrite these 6 files in your repo at the same path (all MODIFIED,
   none are new files, none need a migration):
     next.config.js
     components/sections/work.tsx
     app/portfolio/page.tsx
     app/portfolio/[slug]/page.tsx
     app/blog/page.tsx
     app/blog/[slug]/page.tsx
2. Restart your dev server (next.config.js changes require a restart,
   not just Fast Refresh).
3. No `npm install`, no `prisma migrate`, no new dependency — this is a
   pure code fix, safe to drop in on top of the full update you already
   applied.

ROOT CAUSE
next/image's custom `loader` prop was being passed as a plain function
reference from several async Server Components (page.tsx files with no
'use client'). In the Next.js App Router, any prop crossing the Server ->
Client boundary must be serializable — a plain function isn't (unless
it's a Server Action) — so Next throws exactly this error and the page
hard-crashes.

This was NOT something introduced only by the new features — the same
loader={cloudinaryImageLoader} pattern already existed in app/blog/page.tsx
and app/portfolio/page.tsx before this session's changes. It just hadn't
been hit yet. The two new files that also used the same (pre-existing)
pattern are components/sections/work.tsx and app/portfolio/[slug]/page.tsx
(app/blog/[slug]/page.tsx already existed and got one extra Image element
added, also fixed here).

THE FIX
Configure the Cloudinary loader once, globally, in next.config.js
(images.loader: 'custom', images.loaderFile) instead of passing it as a
prop on every individual <Image>. Next then applies it automatically to
every image on the site, so the loader function never needs to cross the
Server/Client boundary as a prop. Removed the now-redundant
`loader={cloudinaryImageLoader}` prop + its import from the 5 affected
page files.

Three OTHER files in your project still pass `loader={cloudinaryImageLoader}`
explicitly — components/dashboard/image-upload.tsx, app/dashboard/media/
page.tsx, app/dashboard/blog/page.tsx. These were left untouched
deliberately: all three are Client Components ('use client'), and passing
a function prop between two components that are both already
client-rendered never crosses the Server/Client boundary — so they were
never actually broken, and touching them isn't necessary.
